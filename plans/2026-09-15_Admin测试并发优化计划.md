# Admin 测试并发优化计划

## 1. 当前状态和结果

- 状态：实施中
- 结果：不适用

## 2. 关联需求

- 无。本计划属于 CI 验证性能优化，不改变产品能力。

## 3. 背景

`CI - Full Validation` 中 Admin 的生产构建约 10 秒，Admin Vitest 约 7 分钟。现有测试命令启用 coverage、单线程和文件级串行执行，导致 134 个测试无法并发运行。

## 4. 目标

- 保留 Admin 全量测试、V8 coverage 和现有 80% 覆盖率阈值。
- 将 Vitest 调整为最多 2 个 worker，并允许测试文件并行执行。
- 增加 `CI - Full Validation` 的 `full/smoke` 模式；`smoke` 跳过前端 Vitest 和 coverage，保留 Backend pytest、生产构建、四个项目的页面质量基线，并将 Stage C 认证和权限旅程限制在桌面端。
- 通过 GitHub Full Validation 验证并发优化和轻量模式的实际行为。

## 5. 非目标

- 不删除、跳过或拆减测试用例。
- 不降低覆盖率阈值。
- 不让 smoke Artifact 冒充完整 Full Validation Artifact 或满足 `strict` 交接。
- 不修改 Admin 生产构建、Web、Backend 和数据库；E2E 仅增加 full/smoke 执行范围控制，不删除关键旅程。

## 6. 现状分析

- `apps/admin/package.json` 的 `test` 脚本使用 `--maxWorkers=1 --no-file-parallelism`。
- 最近一次完整验证中 Admin Vitest 18 个文件、134 个测试耗时约 411 秒。
- 最慢测试集中在 `StageC.test.tsx`、`SitesManager.test.tsx`、`TaxonomyManager.test.tsx` 和 `AccountsDrawer.test.tsx`。
- Full Validation 的前端矩阵继续始终构建并上传 Admin/Web 生产产物，后续 E2E 依赖这两个产物；smoke 通过 `E2E_PROFILE` 减少重复的移动端 Stage C 认证流程。

## 7. 方案设计

保留 `--coverage --pool=threads`，将 `--maxWorkers=1` 调整为 `--maxWorkers=2`，删除 `--no-file-parallelism`。Vitest 继续执行完整测试和覆盖率门禁，测试文件由最多两个 worker 并行处理。

工作流增加必填的 `validation_mode`，默认 `full`。`full` 执行现有完整链路并上传 `pinjie-full-validation-v2`；`smoke` 跳过 Admin/Web Vitest 和 coverage，继续执行 Backend pytest、两端生产构建和缩减范围的 Chromium E2E，并只上传独立的 `pinjie-smoke-validation-v1`。

## 9. 实施顺序

1. 修改 Admin 测试脚本并保留 coverage 与覆盖率阈值。
2. 增加 `full/smoke` 工作流输入、条件测试步骤和独立验证证据。
3. 增加 E2E profile 接线，smoke 保留质量基线并减少移动端 Stage C 重复流程。
4. 更新测试策略、工作流说明和发布手册。
5. 运行 Admin lint、typecheck、治理检查和 Markdown lint。
6. 由用户人工触发指定 Commit 的 `full` 与 `smoke` 验证，核对耗时、证据和结果。

## 11. 风险与回滚

- 风险：测试间存在未发现的共享状态，增加并发后可能出现不稳定或覆盖率结果差异。
- 风险：操作人员误用 smoke 结果进行严格源码交接。
- 回滚：恢复 `--maxWorkers=1 --no-file-parallelism`，不涉及业务数据和生产环境。
