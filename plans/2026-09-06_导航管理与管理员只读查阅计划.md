## 背景

项目已完成派生初始化。用户确认以个人使用为目标，公开浏览导航，后台统一管理外网站点及其帐号资料；管理员通过 Web 只读查阅全部凭据。导航业务不关联普通用户，既有普通用户能力保留。

## 目标

1. 实现一级分类、标签、单分类多标签站点及一个站点的多条帐号或备注。
2. 统一管理员身份，保留管理会话隔离，新增 Web 只读查阅会话。
3. Web 和 Admin 独立退出；Web 主动退出后禁止自动再次登录。
4. 所有维护在 Admin 完成，Web 只浏览、筛选、查看与复制。

## 非目标

- 不删除普通用户表、注册开关或既有功能，不引入私人用户归属、子分类、帐号共享分配。
- 不实现外网自动登录、抓取、帐号校验、导入导出或密码加密。
- 不执行生产迁移、发布、推送、PR 或部署。
- 不隐式运行 build、pytest、Vitest、Playwright、浏览器自动化或测试数据库迁移。

## 现状分析

- Backend 具有管理员 RBAC、数据库权威会话、CSRF、审计及统一资产能力。
- Web 只接受普通用户 Cookie；Admin Cookie、Origin 和代理路径与其隔离。现有管理员登录不能直接充当 Web 普通用户登录。
- 根 OpenAPI 与 API Client 必须通过生成链路同步。

## 方案设计

### 业务数据

- 五张业务表：`nav_categories`、`nav_tags`、`nav_sites`、`nav_site_tags`、`nav_site_accounts`。
- 分类一级且名称唯一；标签名称唯一；站点必须关联分类；站点标签组合唯一。
- 外网帐号关联站点，不关联普通用户。名称、用户名、明文密码、备注、排序与启用状态分别保存；用户名、密码、备注至少一项非空，密码不自动 trim，不套用管理员密码策略。
- 站点软删除及恢复，下架或删除后公开查询不可见，凭据保留供后台管理。分类仍被任意站点引用时禁止删除；删除标签只解除关联；帐号采用带确认的物理删除。
- 图标复用资产上传，增加导航图标场景及引用保护。

### 认证与权限专项

- 详见 ADR 0016。固定配置 Admin/Web Origin，回调地址不接受任意重定向；本地使用现有两端 Origin，生产地址部署时明确配置。
- 使用短时一次性授权凭证、随机 state 和 S256 请求绑定；浏览器端的查阅会话令牌仅保存在 HttpOnly Cookie。
- Web 查阅会话独立关联管理员与签发时凭据版本，每次访问检查管理员状态与当前查看权限，不跟随普通 Admin Logout 撤销。
- Web 主动退出写入自动登录抑制标记；只有显式登录可解除。匿名探测只尝试一次，不强制普通访客登录、不循环跳转。
- Web 查阅身份不能调用管理写接口；普通用户身份不能读取凭据。
- 外网密码及备注响应不缓存，错误、审计、日志不保存敏感正文；管理员登录密码继续使用 Argon2id。

### 前端

- Admin 沿用 Ant Design、ProTable、公共确认弹窗与现有 HTTP 管道；列表支持与生命周期匹配的批量操作。
- Web 首页展示真实导航，保留既有通用能力入口；沿用 tokens 和基础组件，显示分类、标签、搜索、站点详情和只读帐号列表。
- 明确加载、空数据、失败、无权限、登录失效、复制失败和长文本状态。

## 风险与回滚

- 明文凭据数据库及备份泄露会直接暴露密码，用户已明确选择；禁止将真实凭据用作源码、测试样例或日志。
- 管理员身份跨端是高风险变更，必须复核重放、登录 CSRF、回调绑定、Cookie、缓存与权限失效；未运行真实测试不能宣称安全验收完成。
- 新表采用增量迁移，禁止修改历史迁移。实际数据库升级及权限同步需独立授权。数据写入后不得直接通过删表回滚，应保留新表并回退应用或前向修复。
- 按阶段本地提交保存恢复点，只回退本任务内容，不触碰母版追溯或用户修改。
