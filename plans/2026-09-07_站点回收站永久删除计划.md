# 站点回收站永久删除计划

## 当前状态和结果

- 状态：已结束
- 结果：已完成；源码、生成契约与轻量验证通过，真实删除、权限同步及重型验证未执行

## 关联需求

- `NAV-SITE-001`：站点回收站支持单条和批量永久删除。
- `NAV-CRED-001`：永久删除站点时一并删除所属帐号资料。
- `NAV-ADMIN-001`：独立权限、标准确认、原子批量和审计。

## 背景

当前站点 delete 只设置软删除字段，回收站仅支持恢复。用户确认增加永久删除入口，真正删除数据库记录。

## 目标

- 回收站支持单条和批量永久删除；正常站点仍先移入回收站。
- 删除站点及所属帐号和标签关联，保留分类、标签、图标资产与审计。
- 独立权限、事务锁、全部目标校验和标准确认形成完整流程。

## 非目标

- 不清空整个回收站，不增加定时清理，不删除图标文件，不改变其他实体生命周期。
- 不执行真实数据删除、权限同步写入、数据库迁移、重型测试、Git 提交、发布或部署。
- Web 保持只读，不增加写接口或写操作入口。

## 现状分析

- `SitesManager` 已提供搜索、分页、批量恢复、软删除确认和帐号抽屉；新增操作必须保留当前布局与已有用户修改。
- `NavigationService.bulk_sites` 的 delete 为软删除，restore 只接受回收站站点。
- `nav_site_accounts.site_id` 和 `nav_site_tags.site_id` 已在 Model 和 `20260906_02` 迁移声明 ON DELETE CASCADE，本次不修改数据库结构。
- `NavigationService.write` 复用 AuditCoordinator，先保存审计意图，业务与成功审计在同一事务提交；当前导航维护权限不足以表达独立永久删除授权。

## 方案设计

- 新增 `POST /api/v1/admin/navigation/sites/purge`，专用 `NavSitePurgeIn` 接受 1 至 100 个唯一 UUID，单条和批量共用。返回已有 `NavBulkRead.completed_count`，原有接口和 action 枚举不变。
- 新增 `navigation:purge` 权限及目录版本，含站点所属帐号资料删除权；Router 校验会话、CSRF 与该权限，Service 在事务内重新校验管理员启用状态和最新权限。
- 复用站点按 ID 排序加锁查询，先验证目标齐全且全部已软删除，再用 Repository 显式 DELETE 与 RETURNING 核对实际数量。数据库级联删除帐号与标签关联，不删除被引用的分类、标签和资产。
- 恢复、帐号维护和永久删除共用站点行锁顺序；目标缺失返回 404，已恢复等状态冲突返回 409，整批回滚。审计记录 `navigation.sites.purge`、目标 ID 与结果，不记录帐号、密码和备注。
- 回收站行内红色图标和批量“永久删除”入口由独立权限控制，恢复继续由原维护权限控制；只有任一合法批量操作可用才提供选择框。
- 确认弹窗捕获操作类型及 ID 快照，明确不可恢复及关联删除范围；提交期间禁止重复提交、关闭和冲突操作，失败保留目标和反馈，不自动重试永久删除。
- 成功清空选择、刷新列表、返回有效分页，关闭受影响帐号抽屉并取消及清除对应帐号查询缓存。现有列表失败、空态、工具栏和窄屏滚动继续保留。

## 风险与回滚

- 永久删除提交后无法从回收站恢复，代码回退不会恢复数据；数据恢复需要已验证备份与单独恢复授权。
- 图标资产可能共享，本次仅解除站点引用，保留文件和资产行，避免跨系统删除副作用。
- 新权限启用须核对并同步源码目录、按需分配角色，不由启动过程自动写权限表。
- 无表结构变更；可撤销新接口及 UI 并停止授予新权限，保留既有分类可见性等安全保护。
- 审计失败拒绝或回滚删除，响应丢失时先刷新列表核对，不自动重新发送永久删除请求。
