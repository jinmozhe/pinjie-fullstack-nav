## 背景

当前 Web 前台页面在访问时，会通过服务端与前端生命周期自动触发静默登录探测（`shouldProbeReader` 和 `startReaderLogin?silent=1`），向管理后台发起跨站重定向以探测当前用户是否为管理员。

在实际生产环境中，该机制引发了明显问题：

1. 普通访客在首次打开或刷新前台时，会被自动带入管理端授权流程。若管理端未登录或网络存在延迟，普通浏览直接受到阻塞。
2. 当访客完全未登录管理端时，管理端前端库（`http.ts`）因捕获 401 自动尝试调用 `/auth/refresh` 刷新会话，但由于缺乏 CSRF Cookie 被后端拒绝返回 `403 CSRF_REJECTED`，导致页面卡在授权报错界面，未能正常回跳前台。
3. 2026-09-14，用户明确要求调整逻辑：普通打开和刷新页面完全作为公开访客浏览，不发起任何自动授权跳转；只有用户主动点击右上角“管理员登录”时，才触发登录与授权流程。

## 目标

1. 移除 Web 前台页面加载时的自动静默登录探测，普通访问与页面刷新绝不发起跨站跳转。
2. 保留右上角显式“管理员登录”入口，仅在用户主动点击时前往管理端完成登录与授权。
3. 优化管理后台授权页（`AuthorizePage`），禁止未登录状态下触发错误的 CSRF 刷新请求，保证授权流程轻量可靠。
4. 保持管理员授权成功后返回前台解锁私有分类与站点的现有核心能力不变。
5. 本次任务仅创建计划文档并登记索引，不执行实际源码修改与上线部署。

## 非目标

1. 不修改后端已验证的 OAuth/PKCE 授权码生成与凭据交换逻辑（`nav_reader.py` 及相关路由）。
2. 不变更数据库模型与 Alembic 迁移。
3. 不调整生产环境既有的域名与端口规划。
4. 不在本任务中执行代码修改、打包构建或生产部署。

## 现状分析

1. **Web 端触发链路**：
   - `apps/web/src/app/page.tsx` 和 `apps/web/src/app/top/page.tsx` 服务端调用 `shouldProbeReader()`，将 `autoLogin` 标识传递给客户端 `Navigation` 组件。
   - `apps/web/src/features/navigation/Navigation.tsx` 中的 `useEffect` 监听 `identity.error.status === 401`，当 `autoLogin` 为 true 时，自动调用 `window.location.replace('/api/navigation/start?silent=1')` 发起重定向。
2. **Admin 端响应链路**：
   - 授权页 `apps/admin/src/features/navigation/AuthorizePage.tsx` 加载时调用 `adminApi.me()` 检测会话。
   - `apps/admin/src/lib/api/http.ts` 的 `apiRequest` 拦截到 401 错误，自动调用 `refreshSession()`。
   - 未登录访客因缺少 `pinjie_admin_csrf` Cookie，导致 `/api/v1/admin/auth/refresh` 返回 `403 CSRF_REJECTED`。
   - `AuthorizePage` 捕获到 403 错误，无法识别为未登录状态，直接弹窗报错，阻断了静默跳回逻辑。

## 方案设计

### 1. Web 端改造（转为纯被动按需登录）

- **移除自动探测**：
  在 `apps/web/src/app/page.tsx` 和 `apps/web/src/app/top/page.tsx` 中，停止调用 `shouldProbeReader()`，固定传入 `autoLogin={false}`，或者从组件属性中移除该字段。
- **清除自动重定向副作用**：
  在 `apps/web/src/features/navigation/Navigation.tsx` 中，删除根据 `autoLogin` 和 401 自动执行 `window.location.replace(...silent=1)` 的 `useEffect` 监听器。
- **保留主动点击交互**：
  前台右上角的“管理员登录”链接保持直链到 `/api/navigation/start`（不带 `silent=1` 参数）。只有用户主动点击该链接时，才发起向管理端的显式授权跳转。

### 2. Admin 端改造（防止误触发 CSRF 错误）

- **抑制自动刷新重试**：
  在 `apps/admin/src/features/navigation/AuthorizePage.tsx` 中，调用 `adminApi.me()` 时显式传入 `{ retryAuth: false }`，指示底层请求库遇到 401 时直接向上抛出，不得尝试发起 `/auth/refresh`。
- **未登录流程闭环**：
  当 `AuthorizePage` 收到 401 时：
  - 如果带了 `silent=1`，安全返回前台。
  - 如果是主动点击登录（非 silent），页面平滑重定向到 `/login?redirect=...`，引导管理员完成账密登录，登录完成后自动返回完成授权并跳回前台。
