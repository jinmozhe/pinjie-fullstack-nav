# 站点可选分类计划

## 1. 当前状态和结果

- 状态：已结束
- 结果：已完成；未分类站点可保存，发布与置顶保护、迁移、契约、Admin 适配和轻量门禁已完成，实际迁移与重型验证未执行

## 2. 关联需求

- NAV-CAT-001
- NAV-SITE-001
- BASE-API-001

## 3. 背景

当前站点创建和更新强制提交分类，妨碍批量插入后再补充分类的维护流程。用户已授权将站点分类改为可为空。

## 4. 目标

- Admin 和管理 API 可以保存未分类站点。
- 未分类站点不进入公开导航，也不能被发布或置顶。
- 保持既有分类筛选、回收站、删除限制和公开可见性规则。

## 5. 非目标

- 不新增批量导入接口或修改现有批量生命周期端点的请求结构。
- 不执行共享数据库迁移、数据清理、发布或部署。
- 不改变 Web 公开导航的信息结构。

## 6. 现状分析

`nav_sites.category_id`、`NavSiteIn`、`NavSiteRead` 和 Admin 表单都要求分类。公开查询以分类内连接和启用状态作为可见条件，因此直接放宽字段会造成已发布但前台不可见的状态，需要在写入与批量发布时保留明确保护。

## 7. 方案设计

将数据库外键、ORM 字段和管理 DTO 改为可空；Admin 列表显示“未分类”，表单支持清除分类。公开查询继续依赖分类可见条件。写入 `is_published=true` 和批量 publish 在分类为空时返回冲突；置顶复用保存接口，因此同样受保护。
