# 站点信息抓取计划

## 当前状态和结果

- 状态：已结束
- 结果：已完成；抓取接口、管理端表单、生成契约、测试源码与本地轻量检查完成，重型和真实外站验证未执行。

## 关联需求

- `NAV-SITE-002`：管理员输入网址抓取名称、简介和图标，保存前可以修改。
- `NAV-SITE-001`、`NAV-ADMIN-001`：复用站点维护、资产和管理员权限。
- `BASE-API-001` 至 `BASE-API-005`：沿用唯一 OpenAPI 与生成客户端。

## 背景与目标

已有站点表单需要手填名称、网址、简介及上传图标。新增“网址、抓取、检查并修改、保存”流程，减少录入操作。

## 非目标

- 不执行目标页面 JavaScript，不登录第三方，不绕过反爬，不抓取内网。
- 不自动发布站点，不改变分类、标签、排序与帐号资料，不自动更新历史站点。
- 不部署、不提交 Git、不执行未点名的构建、pytest、Vitest 或浏览器自动化。

## 现状分析

- Admin `SitesManager.tsx` 使用 Ant Design Form 与既有图片上传组件，站点保存通过生成 DTO 和统一请求层。
- Backend 暂无生产 HTTP 客户端；httpx 当前为开发依赖，Pillow 已为运行依赖。
- 图标资产只允许 PNG、JPEG、WebP。抓取时将受支持位图（含 ICO）转换成小尺寸 PNG，保持资产安全策略，SVG 不执行或透传。
- 工作区已有 Web 改版和用户锁文件修改，逐文件补丁保留；依赖命令前保存锁文件字节备份并核对当前版本。

## 方案设计

- 新增受 `navigation:write`、Admin 会话和 CSRF 保护的 POST 元数据端点，仅获取草稿，不写数据库。
- 标准 HTMLParser 提取 Open Graph、title、description 和 icon；无字段时返回明确缺失提示。有文本但图标失败时返回文本和图标失败提示，整页失败使用安全错误码。
- 图标以内存 PNG Base64 返回，Admin 只在保存时通过现有上传 API 创建资产并关联站点；抓取不改原网址、分类等字段。
- 抓取填入未在请求期间修改的名称、简介和图标；缺失项保留原值。关闭表单、更换站点或修改网址取消请求并阻止迟到响应写入其他草稿。
- HTTP 客户端归 lifespan，连接、读写、池和总预算有界；公网 DNS 全量校验后固定连接 IP，TLS 继续校验原域名，每次重定向重新校验。禁用户信息、非 HTTP(S)、非标准端口、私网、回环、链路本地和特殊地址；不透传 Cookie、授权、代理环境或原始错误。
- HTML 最多 1 MiB，图片最多 2 MiB，最多 3 个候选，每次请求最多 3 次重定向，总抓取预算 20 秒，并发最多 4 个，忙时 429；不自动重试或持久缓存。响应只支持未压缩正文，避免压缩膨胀。

## 风险与回滚

- DNS 重绑定、跳转内网和图片膨胀由固定 IP、逐跳校验、字节及像素限额防护；真实第三方可用性不作保证。
- 抓取内容视为不可信纯文本，不能执行其中脚本或指令；SVG 图标需手动改用受支持位图。
- 保存阶段复用上传去重，保存站点失败后保留已上传资产 ID 供重试；取消未保存站点时的资产维护沿用现有上传机制。
- 回滚仅撤回本功能入口、客户端和读取适配器，数据库无迁移；保护此前用户修改，不自动撤回 Git 历史。
