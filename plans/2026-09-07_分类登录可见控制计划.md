## 3. 背景

部分分类及所属站点需要仅供已登录的管理员查阅。当前分类只有启停字段，公开分类和站点查询未按登录资格过滤。

## 4. 目标

- 分类支持“仅登录后可见”，默认关闭，历史分类保持公开。
- 未登录时隐藏受限分类及所属站点，搜索、标签筛选和分页计数遵守同一边界。
- 有效管理员查阅会话可读取启用分类下已发布且未删除的站点；普通用户登录不解锁。
- 退出、会话失效、切换浏览器标签时处理受限内容和请求缓存。

## 5. 非目标

- 不新增普通用户授权、分类级角色分配、标签可见性开关、子分类或业务写入口。
- 不改凭据权限、Admin 登录退出语义及现有批量生命周期操作。
- 不执行 Git 提交、推送、发布、部署和实际数据库升级。
- 未获点名授权的 pytest、Vitest、production build、Playwright 和浏览器自动化不执行。

## 6. 现状分析

- `NavCategory` 与 `NavTag` 目前共用分类输入输出契约和管理界面。
- 公开查询在数据库中过滤发布、删除和分类启用状态。
- `CurrentReaderDependency` 已校验独立查阅会话及管理员当前权限。
- Web SSR 导航读取不携带查阅身份；客户端站点和分类缓存未按身份隔离。

## 7. 方案设计

- 数据库：`nav_categories.requires_login` 为非空布尔字段，默认 `false`，新增增量迁移，不修改历史 revision。
- 契约：分类专属输入输出在现有公共分类字段基础上扩展；标签拒绝登录限制字段，不增加标签存储字段。
- Backend：现有公开入口始终排除受限分类；新增 `/nav-reader/sites` 和 `/nav-reader/taxonomy/categories`，显式声明查阅身份依赖。两类入口共享查询实现，分页和总数在相同过滤条件下生成。
- Admin：分类编辑增加开关，列表增加可见性标识，沿用导航写权限和审计。
- Web：SSR 校验 reader 后选择查询入口，只透传 reader Cookie；公开与查阅查询分别缓存，禁止共享 HTTP 缓存。认证故障明确显示，禁止用旧授权数据继续展示。
- 退出和失效：隐藏受限详情、取消授权请求、清除授权缓存；失去当前分类访问资格时回到全部站点第一页。跨标签退出与现有 BroadcastChannel 协作。
- 契约影响：增加分类字段和查阅端点；公开查询的可见范围收紧，Admin/Web 在本计划同步适配，不维护双版本消费者。

## 11. 风险与回滚

- 旧 Backend 无可见性过滤，配置受限分类后禁止直接回退旧应用，否则会公开受限资料。需要回退时先关闭外部访问并采取前向修复，恢复访问前核对过滤生效。
- 迁移增加非空字段和服务端默认值，需评估目标环境锁表窗口；本任务不执行数据库迁移。
- 删除字段会丢失可见性配置，迁移降级明确拒绝；优先保留数据并前向修复。
- 已看过或复制的站点资料无法收回；服务端每次请求重新授权，客户端依据查阅状态和周期核验更新。
