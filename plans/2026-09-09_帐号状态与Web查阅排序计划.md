# 帐号状态与 Web 查阅排序计划

## 1. 当前状态和结果

- 状态：已结束
- 结果：已完成；全部源码实现、契约与全端轻量门禁通过，未入库脚本作为本地排除项安全隔离，重型验证未执行

## 2. 关联需求

NAV-CRED-001、NAV-WEB-004、NAV-ADMIN-001。

## 3. 背景

Web 当前只展示启用帐号，按手动排序和 ID 排列；Admin 帐号列表只读展示状态，需要进入表单或批量操作完成启停。

## 4. 目标

Web 向有权查阅的管理员展示全部仍存在的帐号，启用在前，同状态按最近更新时间倒序，时间相同时按 ID 升序稳定排列。Admin 帐号状态列提供直接保存的 Ant Design 开关。

## 5. 非目标

不改变 Admin 手动排序、身份核验、站点可见性、物理删除及复制能力；不新增帐号历史版本、数据库迁移、依赖、生产操作或 Git 交付。

## 6. 现状分析

NavAccountRead 已包含 is_active 与 updated_at。Repository.accounts 同时服务 Admin 和 Web，必须限定 Web 排序分支。帐号没有软删除，停用不代表外网真实可用性；updated_at 表示资料最近修改时间。

## 7. 方案设计

- Backend 在原 Web 查询分支取消启用过滤，并按 is_active 降序、updated_at 降序、id 升序查询。Service 的站点检查与 Router 的查阅身份核验保持原样。
- Web 使用现有布局与 tokens，在帐号名称附近标记已启用或已停用，停用资料仍清晰可读且可以复制。使用后端返回顺序。
- Admin 复用帐号 bulk 端点，仅提交单个 ID 和 enable/disable；写权限与非回收站状态控制入口，逐行加载，防止重复及冲突操作，失败显示统一错误。敏感帐号查询及 mutation 保持及时清理，状态请求不携带凭据。
- 无结构性契约调整，导出并核对根契约及生成客户端漂移。
