# 站点名称与域名搜索计划

## 当前状态和结果

- 状态：已结束
- 结果：已完成；名称与域名搜索及追加 Admin 简介搜索移除、移动端工具栏修复已完成本地实现和范围内轻量检查。全目录既有问题及未执行重型验证见下文。

## 关联需求

- `NAV-WEB-007`、`NAV-ADMIN-001`；保留 `NAV-CAT-002` 可见范围。

## 背景

用户要求 Admin 与 Web 搜索同时匹配站点名称和域名。

## 目标

两端支持名称或域名的大小写不敏感包含查询，保留分页、筛选与身份隔离。

## 非目标

不增加全文检索、依赖、数据库字段或迁移，不执行 Git 提交、发布和部署。

## 现状分析

两端共用 Repository；Web 只匹配名称，Admin 匹配名称或简介。网址已校验为无登录信息的 HTTP(S) 地址，允许端口与 IPv6。

## 方案设计

- Repository 在分页及总数计算前使用名称或 URL 主机部分匹配；按用户追加要求，Admin 也不匹配简介。域名匹配排除协议、端口、路径、查询参数和片段。
- 使用 PostgreSQL substring 提取主机并保留 IPv6，复用现有 ILIKE 字面转义。不新增存储字段。
- Web 继续去除关键词首尾空白，搜索与分类标签互斥；Admin 保留分类、标签叠加查询。
- 两端更新搜索提示，Admin 桌面保留 180px 搜索框、自动宽度筛选和图标清空按钮，窄屏布局按追加修正执行。
- 根工作流第 17 节及各端 AGENTS 的查询、权限和契约约束落实于 Repository 与现有组件；通过静态门禁、契约导出比对和差异复读核验。
- SQL 行为依据 [PostgreSQL 模式匹配文档](https://www.postgresql.org/docs/current/functions-matching.html) 的 substring 首个捕获组语义。
