## 背景、目标与非目标

当前 `/x` 在页面源码内维护 `SITES`，生产 Web 使用非 Root 的 Next.js standalone 容器。目标是将全部原始站点迁移到初始化 JSON，并让每次请求读取宿主机挂载文件。保持既有展示、顺序、外链和不收录行为，不增加登录限制、后台编辑、轮询、下载 API 或数据库依赖。

- 运行数据为根目录 `data/x-sites.json`，只提交同目录 `x-sites.example.json` 模板；初始化仅在运行文件缺失时创建。运行文件、临时更新文件和备份不进入 Git 或镜像。
- `X_SITES_FILE` 必须为服务端绝对文件路径。`/x` 通过 `connection()` 等待真实请求，再读取和校验 JSON，不缓存数据、不回退模板。
- 顶层数组，每项为 `name`、`url`、`description` 字符串，名称非空，网址为合法 HTTP/HTTPS 且无重复；保留输入值和顺序。空数组是有效空态。
- 缺少配置、文件不可读、语法或字段错误均记录脱敏类别及字段位置并抛出安全错误，由 `/x` 中文错误边界提供完整重新加载入口。
- Compose 通过必填 `X_DATA_DIR` 将宿主机数据目录只读挂载到 `/app/runtime-data`，禁止自动创建缺失挂载源；容器内 `X_SITES_FILE=/app/runtime-data/x-sites.json`。
- Web 提供 `check:x-sites` 只读文件校验命令，与页面复用同一纯校验模块；Dockerfile 将命令与该模块复制到运行镜像，由 Node.js 24 原生运行，服务器无需安装开发工具链。
- 运维同目录临时文件校验后原子替换，保留 UID/GID `10001` 读取权限；不更换目录本身，反向代理与 CDN 不强制缓存 `/x`。

## 风险与回滚

- 首次启用需先初始化文件和权限，再配置挂载并部署新版 Web；本任务只交付本地变更。
- 正式文件直接截断写入可能引发读取失败，必须通过同目录原子替换更新，备份恢复使用相同步骤。
