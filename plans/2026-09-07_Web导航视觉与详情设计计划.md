# Web 导航视觉与详情设计计划

## 当前状态和结果

- 状态：已结束
- 结果：已完成；桌面与手机方案、Backend、生成契约和 Web 源码及轻量验证已完成，重型测试与浏览器验收未执行。
- 当前阶段：已按明确授权落实设计，进入用户本地人工体验与后续反馈；当前公开数据为空，HTTP 可用性检查未覆盖有内容的布局。

## 关联需求

- `NAV-WEB-001`：公开浏览、筛选和管理员凭据只读查阅。
- `NAV-WEB-002`：首页分类分组预览与完整分类浏览。
- `NAV-WEB-003`：卡片外链与详情打开行为。
- `NAV-WEB-004`、`NAV-WEB-005`：详情资料与帐号排列、无权限隐藏、分类和标签列表跳转。
- `NAV-WEB-006`：移除侧栏底部两个链接，改为居中版权。
- `NAV-WEB-007`：全站站点名称包含搜索，与分类和标签互斥。
- `NAV-CAT-001`、`NAV-CAT-002`：一级分类、图标、登录可见与计数隔离。
- `NAV-AUTH-001`、`NAV-AUTH-002`、`NAV-CRED-001`：保留管理员查阅、两端独立退出及多帐号资料。
- `BASE-WEB-003`、`BASE-WEB-004`、`BASE-WEB-005`、`BASE-WEB-006`、`BASE-WEB-008`：SSR、可访问性、设计 tokens、契约与配置品牌。
- `BASE-API-001` 至 `BASE-API-005`：后续涉及公开契约时遵守唯一生成链与消费者迁移。

## 背景

用户提供 Solo Nav 桌面截图，希望 Web 接近其布局与视觉，先讨论设计，再逐步完善文档。用户已确认按分类分组预览，每组最多 8 个，查看全部进入分类结果；进一步明确卡片仅右上外链图标打开指定网址，其余文本和图标均打开站点详情。

## 目标

1. 建立可持续更新的 [Web 导航端设计标准](../docs/architecture/web-design-standard.md)，明确截图参考、展示层级、响应式、卡片交互和详情方案。
2. 在产品需求基线保存已确认的分组首页与点击规则，避免后续实现恢复成标题直接外跳。
3. 在同一全栈计划记录数据依赖、实施阶段、验证与待讨论事项，后续直接续接原文件。

## 非目标

- 不修改数据库结构、认证权限模型或生产环境；不增加运行依赖，沿用既有原生 dialog、基础控件与 Lucide，使用统一导航 tokens 实现已确认视觉。
- Web 不增加导航业务的创建、修改、删除操作；Admin 保留现有组件和管理能力。
- 不自动增加收藏、推荐、热度统计、抓取、自动登录外部网站或普通用户私人站点；用户明确本期不需要深色模式和置顶。
- 不重设计普通用户登录、注册、用户中心与系统状态页面；按用户要求移除导航侧栏底部用户中心与系统状态链接，保留页面路由及功能和敏感资料保护。
- 本地文档检查点提交已获授权；不执行推送、发布或部署。构建、Vitest、pytest、Playwright 和真实数据库验证需按项目规则另行明确授权。

## 方案设计

### 展示与交互

视觉尺寸、颜色、组件及点击规则只在设计标准中维护完整正文。范围包括分组首页、筛选结果和站点详情；同一个站点卡片组件覆盖首页与结果列表，避免行为分叉。

详情排列和帐号行为已确认，具体标准见设计标准第 6 节；详情内增加分类与标签链接，在当前标签页进入相应列表。进入目标列表时清除无关筛选、回到第一页、关闭详情并清理凭据。卡片主体空白同样打开详情，空分类侧栏保留、首页跳过，搜索仅按全站名称包含匹配且清除分类和标签条件；深色模式与置顶不纳入本期。产品与实施授权均已确认。

### 数据能力规划

- 分组预览与分类完整列表必须使用同一发布、删除、分类启用及身份过滤条件，总数在过滤后计算。
- 不从当前 24 个站点推断首页全部分类；不抓取所有站点到浏览器后再截取，也不无界并发请求每个分类。
- 名称搜索需核对并调整 Backend 查询语义，公开与管理员读取范围一致；不能仅在前端过滤当前分页，也不能继续使用名称或简介共同匹配计算总数。同步评估 Admin 消费者，避免改变其未授权的检索行为。
- 优先评估 Backend 提供有界的分组读取能力，返回分类信息、真实可见总量和最多 8 个预览站点；分类数量较大时分批读取分组，SSR 至少返回首批可用内容。
- 设计阶段先记录能力要求；实施时已读取领域 Router、Service、Repository，端点、批次、排序和错误语义见下文“本次实施细节”。
- 继续区分公开与管理员查阅作用域，凭据只在授权详情请求中按需读取；分组响应不携带帐号字段，不新增公共缓存存储私密数据。
- 若需要新增契约，按 Backend 实现、根 OpenAPI 导出、API Client 生成、Web 适配的顺序执行，并核对 Admin 类型消费者。

## 风险与回滚

- 分组遗漏或计数越权：后端统一过滤，核对零站点、超过 8 个、同排序值和身份变化，不以当前页计数替代总数。
- 点击冲突：详情与外链使用独立语义控件和命中区域，验证一次操作只发生一种行为。
- 敏感数据残留：复用现有查阅会话隔离、失效处理、退出广播与缓存清理，新增分组缓存也纳入相同生命周期。
- 样式扩散：导航 tokens 在导航容器内生效，实施前核对 dialog 与公共按钮的样式继承，不改变其他页面主题。
- 请求规模：分类和预览读取必须有界；超时或部分读取失败明确表达，不能把缺失分组当作空分类。
- 文档阶段可用逐文件补丁修订本次正文；计划文件永久保留。后续源码回滚只处理当前改动，保留用户修改与既有权限机制，不自动执行 Git 历史或数据库回退。
