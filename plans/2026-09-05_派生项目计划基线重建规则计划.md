# 派生项目计划基线重建规则计划

## 1. 当前状态和结果

- 状态：已结束
- 结果：已完成；母版永久保留计划、派生初始化人工清理例外、Tag 与完整 SHA 追溯及初始化后恢复保护规则已同步并通过全部治理门禁

## 2. 关联需求

- `BASE-GEN-006`：派生项目必须保留可核验的母版来源基线。
- `BASE-DOC-001`：项目身份与活动计划通过根索引导航。
- `BASE-DOC-004`：治理规则调整使用全栈计划追踪。
- `BASE-DOC-005`：母版与派生项目分别维护准确的计划保护边界。
- `BASE-DOC-006`：当前文档和交付历史保持可导航且职责唯一。

## 3. 背景

母版现行规则要求派生仓库继续保留母版全部计划原文及其永久登记。独立业务仓库继承的是母版源码能力和治理基线，母版历史计划不属于派生项目自己的实施历史。长期混放会扩大计划索引并增加搜索和任务判断噪声。

用户确认：母版继续永久保留全部计划；独立业务仓库在派生初始化期间允许由用户人工一次性删除从母版继承的计划原文，重建自己的 `plans/` 基线。AI 仍然无权删除计划。

## 4. 目标

1. 明确母版计划在母版仓库中永久保留。
2. 为独立派生业务仓库建立一次性、仅限初始化阶段的人工清理例外。
3. 保留 `plans/README.md`，按派生仓库实际计划重建 `plans/INDEX.md`。
4. 要求派生仓库同时记录母版 Tag 和完整 Commit SHA，确保清理当前工作树中的母版计划后仍可追溯。
5. 派生初始化结束后，恢复对派生项目所有新计划的永久保护。

## 5. 非目标

1. 不删除、移动、重命名或改写母版中的任何历史计划。
2. 不由 AI 删除派生仓库中的继承计划。
3. 不改变源码、API、数据库、依赖、构建、镜像发布或生产部署。
4. 不要求派生仓库保留母版远程地址或建立运行时依赖。

## 6. 现状分析

1. 根 `AGENTS.md`、`plans/README.md` 和 PRD 已禁止 AI 删除、移动或重命名计划。
2. ADR 0004 当前要求派生仓库保留母版计划，需要由新的 ADR 修订派生初始化部分。
3. 文档治理脚本按当前实际计划文件与 `plans/INDEX.md` 进行双向一致性检查，能够支持人工清理后重建索引，无需弱化门禁。
4. Git 历史、母版不可变 Tag 和完整 Commit SHA 可以继续定位已清理的母版计划原文。

## 7. 方案设计

1. 根规则和计划规范加入“派生初始化例外”，严格限定主体、时间、文件范围和结束条件。
2. PRD 调整 `BASE-GEN-006`、`BASE-DOC-005` 和派生项目规则。
3. 新增 ADR 0015，修订 ADR 0004 的派生计划继承要求，保留原 ADR 的历史背景。
4. README、项目结构和 AI 工作流同步当前操作入口与追溯要求。
5. Changelog 记录已经交付的治理变化。

## 11. 风险与回滚

- 风险：将初始化例外误用为日常计划清理入口。
  - 控制：限定为独立派生仓库、派生初始化阶段和用户人工操作，初始化结束后立即恢复永久保护。
- 风险：清理后无法定位母版设计与验收记录。
  - 控制：同时记录母版 Tag 和完整 Commit SHA，并保留母版仓库计划原文。
- 风险：误删派生项目已产生的计划或治理文件。
  - 控制：只允许人工删除从母版继承的 `YYYY-MM-DD_*计划.md`；保留 `plans/README.md`、`plans/INDEX.md` 和派生项目计划。
- 回滚：当前任务只修改文档，可依据 Git 差异逐项恢复。
