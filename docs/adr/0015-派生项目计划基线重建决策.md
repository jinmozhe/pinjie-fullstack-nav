# ADR 0015: 派生项目计划基线重建决策

- 状态：已确认
- 日期：2026-09-05
- 决策者：大仙
- 适用范围：`pinjie-fullstack-base` 及其独立派生业务仓库

## 背景

ADR 0004 建立了计划永久保护和派生仓库保留母版计划的原始规则。该规则能够完整保存母版实现的需求、决策与验证依据，但独立业务仓库长期保留全部母版计划会扩大计划索引，并使母版交付历史与派生项目自身实施历史混在同一工作树中。

独立派生项目已经通过母版不可变 Tag、完整 Commit SHA 和 Git 历史获得源码及历史追溯能力。派生项目仍需要保留计划治理机制，但可以在初始化阶段建立自己的计划基线。

## 决策

### 母版计划永久保留

`pinjie-fullstack-base` 中全部计划原文及其在 `plans/INDEX.md` 中的登记继续永久保留。母版不适用任何派生初始化清理例外。

### 派生初始化人工清理例外

独立业务仓库仅在派生初始化阶段允许使用一次性例外：

1. 用户可以人工删除从母版继承的 `plans/YYYY-MM-DD_*计划.md`。
2. AI 不得执行这些文件的删除、移动或重命名，只能说明范围并在用户操作后核对事实。
3. `plans/README.md`、`plans/INDEX.md` 和已经产生的派生项目计划必须保留。
4. 用户完成人工清理后，AI 按当前实际文件重建 `plans/INDEX.md`，删除失效登记并验证双向一致性。
5. 派生初始化计划结束后，当前仓库全部现存计划及后续新增计划恢复适用永久保护规则。

本例外不能用于日常整理、计划归档、历史瘦身或规避未完成事项，也不能删除派生项目自身已经产生的计划。

### 基线追溯

派生项目必须在 `PROJECT_INDEX.md` 中同时记录：

1. 母版不可变 Tag。
2. 对应的完整 40 位 Commit SHA。
3. 派生类型、当前阶段和业务范围。

母版计划从派生仓库当前工作树移除后，继续通过母版仓库和派生仓库 Git 历史追溯。派生项目不复制母版计划摘要来伪造自己的实施历史。

## 与 ADR 0004 的关系

本 ADR 只修订 ADR 0004 中“派生仓库继续保留母版计划原文和登记”的要求。ADR 0004 对全项目索引、全栈计划、永久登记、母版计划保护和日常计划生命周期的其他决策继续生效。

## 代价与风险

1. 派生项目当前工作树不再直接提供母版计划全文，查阅时需要使用母版仓库或 Git 历史。
2. 人工清理范围错误可能删除派生项目计划，因此必须保留派生初始化计划并在操作后执行索引双向检查。
3. 初始化阶段结束后不能再次使用本例外，后续计划数量增长仍通过索引导航解决，禁止自动清理。

## 验证要求

1. 母版计划文件和 `plans/INDEX.md` 登记保持完整。
2. 根规则、计划规范和 PRD 对操作主体、阶段、范围及结束条件表述一致。
3. 派生项目同时记录母版 Tag 和完整 Commit SHA。
4. 派生项目人工清理后，`plans/` 实际文件与重建后的 `plans/INDEX.md` 双向一致。
5. 派生初始化结束后，计划永久保护规则继续生效。
