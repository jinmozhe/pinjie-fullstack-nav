# ADR 0017: Admin 删除操作统一确认决策

- 状态：已实施，本地轻量验证通过，动态交互验收未执行
- 日期：2026-09-07
- 决策者：大仙
- 关联计划：[Admin 删除操作统一确认计划](../../plans/2026-09-07_Admin删除操作统一确认计划.md)
- 关联需求：`NAV-ADMIN-001`、`BASE-ADMIN-004`、`BASE-ADMIN-007`。

## 背景与决策

用户明确要求管理端所有“移入回收站”“删除”等操作增加二次确认，防止误点击。本决策局部替代 ADR 0010 中“仅物理硬删除确认、软删除直接提交”的交互约定，其余认证、授权和审计决策保持有效。

1. 立即持久化的软删除、硬删除和已保存图片移除，单条与批量入口均复用 `StandardConfirmModal`，说明操作目标、影响与恢复能力。
2. 保留一个标准确认弹窗和固定“确定”“取消”按钮，不要求密码；用户删除原因作为可选业务表单嵌入同一弹窗。
3. 点击入口时保存目标 ID 集合或 revision，取消不写入，执行期间禁止重复确认和关闭，失败保留目标并提供明确错误。
4. 仅修改未提交表单草稿的图片移除、启停、恢复及其他非删除操作沿用现有交互；不增加管理员删除接口或日志删除入口。
5. 确认弹窗仅用于防误操作，Backend 会话、权限、CSRF、事务与审计继续独立执行。

## 代价与备选方案

软删除虽可恢复，仍会中断公开展示或撤销用户会话，因此接受多一次确认的操作成本。继续直接软删除不能满足用户防误触要求；增加密码校验会改变认证机制，不在本次范围内。

## 验证与回滚

默认验证 Admin 类型、Lint 和相关文档门禁；补充取消不请求、确认目标、失败重试和重复提交回归测试源码，未授权运行 Vitest 和浏览器自动化。回退仅撤销本次 UI 和当前规则补丁，不改变后端删除语义，不删除历史 ADR 或计划。
